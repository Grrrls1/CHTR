# Ordered Stroke：epoch 20 全验证集评估报告

报告日期：2026-10-30（Asia/Shanghai）。训练任务：`ordered_stroke_full/job_679`。

## 1. 结论

当前选优 checkpoint（原名 `best.pt`，现名 `ordered_stroke.pt`）对应完成 **epoch 20、step 141560** 的模型。选优依据为第一阶段自由生成的 `free.ordered_mask_iou`，从 epoch 10 的 **0.65248406** 提升至 **0.71572567**，增加约 **0.06324（6.32 个百分点）**。它不是按整字轨迹 IoU 或验证 loss 选出的模型。

epoch 20 的主要结果：整字轨迹 IoU **0.80860332**，按顺序笔画轨迹 IoU **0.62702208**，笔画数量完全正确率 **71.73%**，严格笔画序列通过率 **55.35%**。与 epoch 10 相比，字形、逐笔结果和数量准确性整体改善；`cls` 略升，teacher-forced `terminal_recall` 略降，不能表述为所有指标均改善。

训练已按用户要求停止；本报告只解释已有评估产物，没有重新评估或修改模型。

完整推理流程是：**输入图像 → 按顺序生成笔画掩码与起点 XY/笔宽 → 用预测掩码保留原图笔画区域、其余置白 → 冻结点模型生成每笔 XY/笔宽序列 → 栅格化轨迹后评估**。自由生成与级联评估不使用真实掩码、真实起点或真实笔画数量作为推理条件；真实标签用于计算指标。

本次配置的总损失为：

```text
loss = 4×cls + 5×mask + 5×dice + 5×box
       + 2×giou + 5×start + 1×width + 1×auxiliary
```

`auxiliary` 是辅助层各自使用上述分项权重计算后再取层平均的结果，不是主输出分项的简单平均。表中 loss 及其分项没有统一物理单位，不应将其直接解释为像素误差。

teacher-forced `mask_iou=0.8261` 高于自由生成 `ordered_mask_iou=0.7157`，与真实历史条件更容易、自由生成会累积误差的设定一致；二者的分母和计数惩罚也不同，差值不能单独作为误差累积的精确度量。

### 5.1 两种轨迹 IoU 的公式与区别

设某字真实笔画数为 n、预测笔画数为 m；真实第 k 笔轨迹栅格区域为 G_k，预测为 P_k。IoU(A,B)=|A∩B|/|A∪B|。

```text
整字轨迹 IoU = IoU(所有 G_k 的并集, 所有 P_k 的并集)
按顺序笔画轨迹 IoU = Σ[k=1..min(n,m)] IoU(G_k,P_k) / max(n,m,1)
```

两者都先逐字计算，再对 8121 个字符取算术平均，长字与短字权重相同。第一阶段 `ordered_mask_iou` 使用相同的序号对齐和数量惩罚思路，但比较的是第一阶段预测掩码，而不是点模型生成轨迹的栅格图。

- 整字指标看合并后的最终字形重合程度，不要求笔画身份或顺序正确。冗余轨迹若完全覆盖已有区域，也可能不降低并集 IoU。
- 按顺序指标严格按序号一一对应，不做 Hungarian 匹配或最优重排。未配对笔画通过较大的分母计为零贡献；漏掉中间一笔还会导致后续序号错位。
- 例如“十”的横、竖形状与位置完全正确，但预测为先竖后横：整字 IoU 可为 1，按顺序笔画 IoU 则因横对竖、竖对横而很低。
- 两种栅格 IoU 都不直接测量单笔内部书写方向；同一路径反向生成，栅格区域仍可能完全一致。

本次 0.8086 与 0.6270 的差异说明：合并字形的重合度高于逐笔对应的重合度。这个差异同时受笔画数量、序号错位、逐笔几何和区域合并影响，不能全部归因于笔顺错误。

### 5.2 对齐误差、计数与聚合口径

`aligned_*` 只比较各字前 min(n,m) 对同序号笔画，不保证这些笔画在语义上对应正确，也不覆盖未配对的缺失/多余笔画。因此必须结合数量指标和 ordered IoU 一起看，不能只用较低的 aligned 误差断言端到端效果好。

起点误差逐笔统计，再按配对笔画数汇总。轨迹几何误差先对每对笔画计算，再按配对笔画平均。轨迹长度不同的情况下，取两条序列点数的较大值（至少 2 点），在归一化序列进度 [0,1] 上线性插值，比较 XY 和笔宽，**包含预测首点**；不是按弧长对齐，不是 DTW，也不是真实时间对齐。每一对笔画权重相同，不按轨迹点数加权。

数量关系核对如下：

```text
真实笔画数 = 配对笔画数 + 数量缺口 = 79816 + 3303 = 83119
预测笔画数 = 配对笔画数 + 多余笔数 = 79816 + 670  = 80486
预测−真实 = 670−3303 = −2633
每字数量 MAE = (3303+670)/8121 = 0.48922546
正常结束轨迹 + 截断轨迹 = 80482+4 = 80486
```

这些“缺失/多余”计数由每字笔画数差得到。笔画数相同但预测错了笔画，不会增加它们；不能将 3303 解释为经过形状匹配确认的真实漏笔总数。

## 6. epoch 10 → epoch 20 的变化与当前短板

- 自由生成 ordered mask IoU：0.6525 → 0.7157，提升约 6.32 个百分点。
- 笔画数量完全正确率：61.63% → 71.73%，提升约 10.10 个百分点。
- 严格笔画序列通过率：47.38% → 55.35%，提升约 7.97 个百分点。
- 整字轨迹 IoU：0.7807 → 0.8086；按顺序笔画轨迹 IoU：0.5656 → 0.6270。
- 按数量计算的缺失笔画：5280 → 3303；多余笔画：682 → 670，改善主要体现在数量缺口减少。
- 起点二维距离误差：19.83 → 15.82 px；轨迹末点距离误差：26.64 → 21.60 px，仍存在明显空间偏差。
- 点数完全相同比例仅 4.70%，但它是序列长度诊断项：相同几何路径可采用不同点数，点数不一致不必然表示字形失败。
- 点模型轨迹截断 4 条，占预测轨迹约 0.00497%；终止率较高，但不能代替质量指标。

相较 epoch 10，当前模型在验证集上的总体表现提升。仍需关注逐笔完整性、同序号对应以及起点/终点位置偏差。仅有这两个评估时点不足以判断更长期收敛或过拟合；这些指标也没有给出外部书法风格上的泛化结论。

## 7. 对外部书法图片单独推理的参考

epoch 20 的选优 checkpoint（当前名为 `ordered_stroke.pt`）可作为本次外部图片推理的基线。验证集指标描述的是已有 val 分布；新字体、书写风格、背景、裁剪和笔画粘连情况变化后，效果需要实际检查。

外部图片若无真实逐笔掩码和轨迹标注，就不能直接得到与本报告同口径的 IoU。建议查看原图与预测轨迹叠加、逐笔播放、笔画数量、漏笔/多笔和起止点。仅看合并后的整字效果，可能掩盖笔顺或单笔划分问题。
